# Changelog

## 0.2.10 (in progress)
- **Cloud sync is part of the kit** (`scripts/cloud.sh`, `core/git.md` › Cloud sync, `INSTALL.md` step 6): optional, with `cloud_sync: on` in the preferences (default `off`; turning it on is the standing OK for its pushes, to the cloud remote only). It keeps one private `cloud/<branch>` per work branch, carrying the kit so a Claude Code cloud session can use it: sync down at the start of a Present session (`status`, then `land`), sync up when work closes (`prepare`, then push the work branch). The cloud remote is `origin`, or a separate private remote set in local git config `jacquard.cloudRemote` when origin is shared. `project.md` › Git names it; `/kickoff` and `/jacquard-update` mention it and set it up; the permissions template allows `cloud.sh status` only. It never runs during Away.
- **No more loop between `land` and `prepare`:** `prepare` no longer merges the work branch into the kit branch, where commits copied by `land` collided with their originals. It writes one sync commit, the work branch's files plus the kit on top of the cloud's tip, so it cannot conflict, and `status` counts from it. Its working folder is always removed, and one left open by an older version is named with the command that closes it. A `land` that stops on a conflict is finished with `git am --continue`, or with the printed commands that keep this computer's version, and run again: what already landed is skipped (cloud commits are matched by author, date and exact subject). `land` says which local commit each cloud commit became. `away/x` and `x` share `cloud/x`: the other branch may take it over only once it holds that work, or with `--take-over` when the followed branch is gone and the user says its work is not wanted. A one-line record left by an older copy counts only when it is not older than the newest sync commit, so the first run after upgrading does not re-apply landed work.
- **The project's own `CLAUDE.md` reaches the cloud untouched:** the kit's instructions now go in `CLAUDE.local.md` on the kit branch, as on the computer, and the cloud's edits to `CLAUDE.md` land like any other file. A branch that tracks a path the kit writes (`.claude/settings.json`, `.claude/skills`, `.claude/agents`), or tracks one as a link, is refused instead of overwritten. The local folder's name is read from `CLAUDE.local.md` and must be plain.
- **What may leave and what may come back** (security review): the remote's one push URL must be a plain GitHub address of a private repo with no other collaborators (a second URL or a pushurl elsewhere is refused). A repo that deploys or runs workflows needs the user's yes to exactly what was found (`git config jacquard.cloudDeployOk "<list>"`, asked again when it grows), or a separate private remote. `land` names the landed files that run or give instructions (`package.json`, hooks, workflows, `CLAUDE.md`, `.claude/`), for the user to see before any check runs. A token inside a remote URL is never printed. Only the installed kit's tracked files travel, and the preferences only if the personal layer versions them. `land` checks the cloud's documents before anything lands: only plain files of the travelling set (no links, no dotfiles, no unusual names) that the personal layer would not ignore. The cloud's settings deny edits to the kit's own files and pushes to `main`. `status` warns when the remote stopped being private. A document changed in both places waits as `<file>.cloud`, and `prepare` refuses until it is merged.
- New script test `tests/scripts/cloud.test.sh` (a local repo stands in for the private remote, `gh` is simulated); new prompt test `tests/core/cloud-sync.md`.
- **Reviews that cost what they are worth** (`core/review.md` › Plan review and Rounds, `core/economy.md` › Estimating cost): level-2 work gets one review of its plan before any code (structural level-1 work too, by the engineering advisor), so design mistakes surface before they are built; it is part of the level-2 floor. Fixes get one re-review by a fresh subagent that receives only the findings, the fix and what it touches, at the same tier for level-2 work; a reviewer is no longer continued round after round. A finding the builder judges wrong goes to the re-review with the reason instead of being fixed. If that re-review finds a new Blocker or Major, the batch stops there: the finding becomes an item marked `blocks: <branch>`, first in Now and on the index's `Now:` line, the branch is not integrated (`/back` says so instead of offering it), and the next Present session starts with it. The plan review has no re-review: the review of the built work checks its findings were applied. Minors are fixed in the batch only when contained; the rest is recorded. A contained Minor the re-review finds is fixed right away with no further review: what a round costs is the next review, not the edit. Every plan that runs reviews states their cost, and a block or batch with more than one level-2 item, or over ≈ 8 subagent runs, is proposed as several blocks.

## 0.2.8
- **Permissions template renamed** to `templates/project/claude-settings.local.template.json`, so the deny rule `git add *settings.local.json*` (unchanged) no longer blocks committing it. Kickoff copies it into `.claude/settings.local.json` as before; `/jacquard-update` compares against it. Projects need no change.
- **Fewer prompts for commands with no risk** (permissions template, kickoff, `core/work-modes.md`): the template allows the kit's `roadmap-index.sh --check`/`--write` on the project's roadmap (exact rules: a wildcard would let `--write` rewrite any file with markers), and lists the personal-repo project folder under `additionalDirectories` (kickoff fills it from `readlink -f <local>` and checks it ends in `/projects/<slug>`), so a terminal write into `<local>` through its link no longer always asks; in auto mode the classifier decides. Kickoff turns `{{CHECK_COMMANDS_AS_BASH_RULES}}` into one exact allow rule per check and test command, never one for a runner like `npx`. Read-only commands get no rule: Claude Code already runs them without asking by default, and a rule like `Bash(sed *)` would also allow `sed -i`. The Away gate's audit also counts the commands Claude uses along the way (checks, tests, terminal writes into `<local>`), not only the plan's. `roadmap-index.sh` now counts its markers only as whole lines, one start then one end, and refuses anything else without touching the file. Every spelling of it in the kit matches the rule. New script tests `settings-template.test.sh` and `roadmap-index.test.sh`; existing projects get the change through `/jacquard-update`.
- **QA always closes an Away block** (`core/away-run.md` section 8, `core/review.md`, `/back`): at every intensity, `-s` included, every task the block built without its own QA gets QA in the review block, together over the block's diff. It is never skipped for lack of room: if the block is cut first, `/back` runs it before the report; only the advisors can become "to test together". New cases: `/away` C7, `/back` C5.
- **The Away guard expires** (`scripts/away-guard.sh`): `on <local> HH:MM` takes the block's end time, and the marker keeps, on a second line, when the guard stops denying: three hours after the end time (room for the closing reviews), or 12 h after `on` when the block has none; `/away-resume` passes its own end time, never the original block's. A user who comes back without `/back` is no longer left with every prompt denied; an expired marker is cleared at the next hook. A marker without that line (0.2.7) never expires; a garbled one keeps the guard on. The template's allow rule for `on` ends in ` *` to accept the end time (projects: `/jacquard-update`). Portable time arithmetic.
- **The installed kit is protected** (permissions template, `INSTALL.md` step 4): the template denies `Edit(~/.claude/jacquard/**)`, since the kit's scripts run from hooks and allow rules without asking. `~/.claude` alone did not stop it: in auto mode a write there goes to the classifier. INSTALL calls the folder a trust boundary, changed only by the user installing a release tag, gives the same deny for `~/.claude/settings.json` to cover every project, and says what the rule does not stop (redirects written with `~` ask instead, `cp`, scripts that write files themselves, git operations inside the folder). Existing projects: `/jacquard-update`, or that user-level deny. Only `Edit(path)` rules are consulted for writes; the template test now refuses `Write(path)` rules.
- **Reviewed binaries can be published** (`scripts/privacy-check.sh`, `personal/privacy-terms.txt`): a line `=<id> <path>` in the private terms file allows one binary at that path with that exact content (`<id>`: `git hash-object <path>`, run in the repo), in all three modes; any change to the file, the same file at another path, or a path with a newline is refused again. Compressed files (zip, docx, gzip…) can never be allowed: nothing can read inside them. An exception never covers text. The plain text inside an allowed binary (ASCII, UTF-8 and UTF-16 runs, such as an XMP or EXIF author or a linked-file path) is still checked, UTF-16 from either byte offset: runs of 24+ bytes for every term and the patterns, runs of 6–23 for terms of 4+ characters only (the thresholds are named once at the top of the script). Shorter checks would fail on noise: in image data, short runs give email- and path-shaped strings and short words by chance (measured on random 1–5 MB files; with these rules 15 of 15 pass in all modes, and no random run reached 18 bytes); the extraction is linear, so a 5 MB file takes seconds. It is a backstop: compressed or numeric metadata (GPS, most PDF properties), base64 inside the file, a lone 3-letter name and Latin-1 text stay invisible, so removing metadata is the real protection, and the refusal says so. In commit and push checks, what git calls binary is no longer pasted into the patch stream and is read whole instead. A malformed `=` line, a bare one included, stops the check. Needs the installed kit at 0.2.8, since the hooks run that copy.
- **Shared harness for script tests** (`tests/scripts/lib.sh`): the scratch folder, `fail`, a git identity isolated from the user's config and the closing line are defined once and sourced by every `*.test.sh`; behaviour unchanged.
- **Short terms match as whole words** (`scripts/privacy-check.sh`): a term of 5 characters or fewer that starts and ends with a letter or digit is found only as a whole word, so it no longer shows up by chance inside hashes, tokens or longer words (`Ana` in "banana"); longer terms still match anywhere. A handle that glues a short name to letters, digits or `_` (`ana_dev`) needs its own line, and a handle is listed without its `@`; the terms template says so.

## 0.2.7
- **Away guard** (`scripts/away-guard.sh`, hooks in the permissions template): a technical backstop so an Away block never stalls on a prompt the gate's audit missed. `/away` turns it on after the OK, once the steps the user chose to run while present are done; `/away-resume` turns it on in its new session; `/back` turns it off first, and so does the natural end of the block. While it is on, a `PermissionRequest` hook denies the prompt with a message telling Claude to use a safe equivalent or park the step, and an `Elicitation` hook declines an MCP server's question. The marker (`<local>/away/.away-active`, at the repo root whatever the current folder) holds the Away session's id, taken from the hook input, so a second session in the same project is never affected; a `SessionStart` hook clears it when the Away session is resumed, cleared or forked, and keeps it on compaction. It only ever denies or declines, never allows, and never denies its own switch-off (only the bare `off` command, nothing chained). The gate's audit covers the `on`/`off` commands; a test checks that every spelling in the rules matches an allow rule. Kickoff fills `{{LOCAL_FOLDER}}` in the hooks; `/jacquard-update` offers them once the installed kit has the script; the personal layer's `.gitignore` template ignores the marker (existing personal repos: add `projects/*/away/.away-active`). The marker's session id comes from the environment on `on` and from the hook input afterwards: that they match after `/clear` is part of the real-session check.
- **Privacy check reads encoded content** (`scripts/privacy-check.sh`): UTF-16 (with or without BOM) and 8-bit text that is not UTF-8 (read as Windows-1252) are converted and checked; base64 runs (standard or URL-safe, 8+ characters) are decoded at every alignment, so a glued prefix does not hide them, and their text fragments are checked; binary or compressed content cannot be read, so it is refused and listed, including a long base64 run of binary data or compressed data in base64. `--staged` and `--objects` read every added or changed blob the same way. Fails with exit 2 where accents cannot be folded (no UTF-8 locale). Report lines are cut at 300 characters. A 2 MB line takes seconds, not minutes.
- **Privacy check, smaller fixes:** the top-level `LICENSE` copyright lines are exempt from terms only (now also in `--staged` and `--objects`, so its first commit no longer blocks a push to a new remote), still checked for patterns, and a file named like the old label, or a `LICENSE` elsewhere, no longer hides content; macOS portability (no `find -printf`; picks `C.UTF-8` or `en_US.UTF-8`; byte-wise tools run under `LC_ALL=C`; handles iconv builds that write `'e` for `é`). UTF-16 without a BOM needs NULs in a third of its bytes; base64 padding counts toward the 8 characters; UTF-16 and zlib inside base64 are caught.
- **Pre-push checks against the remote's real refs** (`scripts/hooks/pre-push`): it lists what the push URL has (`git ls-remote`, 60 s limit where `timeout` exists) instead of trusting the tracking refs, which after a `remote set-url` describe the old URL; if it cannot, it says so and checks every commit. An SSH key without an agent asks for its passphrase twice.
- **Pre-commit guard:** also refuses a commit on a detached HEAD outside a rebase, cherry-pick, revert or bisect (it would belong to no branch and could reach main with a push of `HEAD`).
- **Away branch rule** (`core/git.md`), now one case per line: on main, a new branch; already on `away/…`, continue there; on another work branch, `away/<that-branch>`; nothing tracked changes, no branch.
- **QA as a defined subagent** (`agents/jacquard-qa-reviewer.md`, pilot of one): read-only tools (`Read, Grep, Glob`) and a cap of 40 turns, linked into `~/.claude/agents/` by `INSTALL.md` step 2. `core/review.md` launches QA with it when it is listed among the subagent types, with the model and effort still passed per launch; the prompt carries the check results, since QA cannot run commands. Other reviews stay general-purpose until the pilot is measured with `/retro`.
- **Script tests** in `tests/scripts/` (guard, privacy check, git hooks), run together by `tests/scripts/run.sh`; new prompt cases for `/away`, `/back` and QA.
