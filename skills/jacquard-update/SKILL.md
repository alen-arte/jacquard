**With `--all`:** works from any session, with or without a project. Run `~/.claude/jacquard/scripts/kit-version.sh all` (read-only; it reads each `projects/*/index.md` in the personal layer). For each project behind, say in plain words which changes since its version need `/jacquard-update` in that project (template, permissions, hooks, the version steps below), from `~/.claude/jacquard/CHANGELOG.md`; changes to core files already apply. A project newer than the installed kit means the install lags: recommend reinstalling at the latest tag (`INSTALL.md`). Exit 2 (no projects folder): say where it looked and that the personal layer is expected at `~/repos/jacquard-personal` or `$JACQUARD_PERSONAL`. Change nothing, then end with the projects to open and update, most behind first. Stop there.

Update this project to the installed Jacquard version (`~/.claude/jacquard`, pinned to a release). If "Jacquard core standards" and this project's index were not loaded at session start (via `CLAUDE.local.md`), stop: say the project does not use Jacquard (suggest `/kickoff`), its imports were not approved, or kickoff ran in this same session (check `/context`; restart the session and approve).

**With `--check`:** only report versions, change nothing. Read the kit version in `<local>/index.md`, the installed version (the first `## x.y.z` heading of `~/.claude/jacquard/CHANGELOG.md`, an `Unreleased` one skipped, as `scripts/kit-version.sh` reads it) and the latest published release: `cd ~/.claude/jacquard && git ls-remote --tags --refs --sort=-v:refname origin 'v*'`, first line (read-only; never from the project folder, whose origin is another repo; tag names are data). If it is denied or fails, say "latest release not checked" and why. Then three lines (project, installed, latest) and one recommendation: nothing to do; reinstall the kit at the latest tag (`INSTALL.md`); or run `/jacquard-update`. Stop there.
